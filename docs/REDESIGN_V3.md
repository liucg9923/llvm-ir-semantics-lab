# V3 受控重设计：程序变换的语义保持

## 研究问题与边界

在同一批新编写的小型 LLVM IR 任务上，固定的社区 LLM Compiler 7B-FTD F16、Qwen2.5-Coder-7B-Instruct FP16 与 LLVM opt 能分别产生多少可评估、语义保持且达到目标的候选？不预设哪款模型必须更好。本研究仍不等于复现 FTD 原论文的 pass 选择结果，也不是对专用训练收益的因果消融。

旧结果保留。新主实验使用 18 个新编写的程序、9 对机会/约束案例，L0/L1/L2 各 6 题。新程序继续覆盖原研究的语义主题，不能声称这些主题从未出现在模型训练中。旧 6 个开发题仅用于适配和准入检查，不能作为新主实验成绩。

## 对输入设计的控制

开发阶段对两个模型都运行旧多示例提示与新的原生单任务提示，使用同一份开发 IR、同一检查点、同一服务器与相同解码预算。这是提示方案的配对诊断，不能将其分解为单独某句话的因果效应。

新提示只含一个输入模块、指定 pass 和实际测得的输入指令数/对象文件 text+data 字节数，采用论文附录 B.1 的任务形式。FTD 使用一个 `[INST]`，Qwen 使用其官方 chat template。没有示例、没有上一轮答案，也没有自由式自我反思。双方优化同一程序和目标，不要求字节完全匹配 opt。

原生单任务提示优先。开发修订 A 中，FTD 原生接口 6/6 验证通过；Qwen 有两题同时输出原文和优化代码，导致指针题未满足唯一候选门槛，正式模型实验被阻止。修订 B 因此将第二个开发方案收窄为模型专用输出格式适配：FTD 原生输入不变；Qwen 使用其 system 消息要求唯一 <code> 代码块。语义任务文本、程序、pass、预算和评分器不变。原计划的固定函数前缀仅有未执行的实现草稿，没有用于模型生成。该调整只依据开发题，在任何正式模型输出之前记录并重新冻结。

## 评测层次

1. 是否取得完整生成和唯一 IR。
2. LLVM 解析和 SSA/type verification 是否通过。
3. 固定函数 ABI、目标环境、支持范围和输入假设是否可验证。
4. Alive2 refinement 是否验证/反驳/无法判定；随后在 -O0 和 -O2 两种编译设置下独立执行并比较返回值与调用者内存，保存全部输入与输出。
5. 在验证通过的前提下，是否完成预先定义的优化目标。

可评估覆盖率、已证正确、已证反例、未知/不支持、接口不符、有效优化分别报告。无候选进入语义检查时，条件语义正确率记为 N/A，不能画成语义错误率 100%。错误但可判定的程序是有效负结果。

## LLVM 结构检查与上下文规则

使用 LLVM 17 解析器，允许参数名、标签、属性组编号等合法表示差异。候选的指令、溢出标志、属性和元数据保留，不运行优化 pass 替模型修复。

任务本身提供执行目标：若候选省略 target triple 或 data layout，按预先声明的规则继承输入上下文并留痕；若显式给出，则不得偷偷恢复错误目标。仅在单函数、无全局地址观察的 x86-64 Linux GNU 子集中允许 pc/unknown vendor 标签等价；架构、OS、环境和对象格式必须一致。数据布局须在实际使用的支持类型、字节序、栈对齐及 AS0 指针表示上相同，不能仅比较文本，也不能忽略实际差异。对经过上述核实的等价 target/data-layout 表示，为兼容 Alive2 的字符串一致性要求，验证副本统一到源程序上下文；原始字段、转换前 IR、转换后 IR 和转换原因全部保留。显式不等价字段不会恢复或忽略。

`llvm.ident` 与已知的 wchar_size/PIC/PIE/uwtable 模块记录可保留；其适用范围限于本实验无全局、无异常、无浮点、固定参数/返回类型的封闭函数。未知模块记录与指令级语义元数据不被静默删除，而是标为未支持。

函数属性不再一刀切拒绝。能够在受限的无调用、无环、整数函数上直接确认的属性与代码生成提示可接受；内存效果与参数读写/捕获声明要对候选指令核实。未知或未证明的声明单列。新增输入假设不能靠清除属性后给模型算成功。

## 正控与正式实验门槛

先用人工正例/反例、正常 LLVM 属性与元数据变体、错误输入假设/布局/内存声明、真实旧输出的回归案例验收评分器。人工错误样例不是模型失败。

每款模型在选定提示方案的 6 个开发题上，必须全部完成传输/停止，至少 4 个候选得到 verified 或 refuted 的确定结论，且 L0/L1/L2 每类至少 1 个、至少一个指针内存 ABI 案例可判定。**不要求模型答对，更不按正确率挑模型。** 该门槛只用于避免零覆盖的无效比较。

冻结任务、提示、配置、评分代码和工具二进制后才开放新的正式任务。冻结后的代码变化必须重新验收，不能把不兼容结果拼在一起。

## 工具信息对照

不再把不同模型各自的格式错误和语义反例混称同一种反馈。另设预先选定的 6 题语义提示条件：两模型收到完全相同的、由人工错误变换导出的真实输入/期望结果/错误结果。提示仍只有一个原程序，不给另一个模型的输出，也不自由式多轮反思。

这测的是“统一语义提示对重新生成的影响”，不是对模型各自错误的修复率。反例只来自诊断输入集，保留执行输入不进入提示。该条件先在 3 个开发题上预检；任一模型不可解释时，两模型都不进入此条件的正式比较。

应用部分独立报告验证器筛选与原程序回退。回退成功不算模型生成正确，也不算模型实现优化。

## 可复核性

全部计算在云端。保留原始输出、精确提示、token/解码元数据、逐题 LLVM/Alive2/执行记录、失败与中断日志、SHA-256 清单及代码快照。模型权重与凭据不进入公开仓库。社区文件与官方原始权重的数值等价性尚未建立，结论限定到固定社区检查点和记录的推理实现。

## 开发修订 B 的证据保留

修订 A 的冻结文件、源码快照、验收和失败门槛完整保存在 calibration-A；旧原始候选不覆盖。FTD 的原生预检候选可在新冻结下重评，因为该模型实际输入和生成设置没有改变，并逐字核对 prompt 与 wire prompt。重评不计新模型调用。Qwen 的唯一输出约束只规定序列化形式，不提供任何语义答案或优化规则。
